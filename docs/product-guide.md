# 功能导览

给产品、运营，不需要看代码。讲这个站有哪些功能、读者能看到什么、后台能做什么。想了解代码怎么组织，见 [架构](architecture.md)；想调整精选标准或归组逻辑，见 [精选与校准](selection.md)、[事件归组](grouping.md)。

## 一条资料是怎么变成读者看到的内容的

```
信源（RSS / 网页 / JSON 接口 / X 账号 / 公众号 / 外部推送）
  → 判重，抓原文
  → 预筛（判断和这个行业有没有关系）
  → 独立打两次分（同一份标准，分数够了才算"精选"候选）
  → 写中文标题、摘要、推荐理由；外文做全文翻译
  → 和别的报道同一件事的，聚成一个"事件"
  → 按事件计算热度（独立来源越多越靠前）
  → 分数过门槛、确认不是精选里已有新闻的重复 → 进"精选"
  → 每天编一期日报；每周、每月再从日报汇编成周报、月报
```

读者打开网页看到的，都是已经跑完这条流程、存进数据库的结果——不会因为有人打开页面才临时去调用模型。

## 读者能看到什么

| 入口 | 内容 |
|---|---|
| 首页 | 当前精选：分数够、确认不重复的新闻，一件事只占一条 |
| 全部动态 (`/all`) | 预筛通过的全部内容，不管有没有入选精选 |
| 热点榜 (`/hot`) | 按事件排的热度榜，48 小时窗口、独立来源越多越靠前、24 小时热度减半；涨得快标"上升"，新出现标"新" |
| 事件页 | 一件事聚合的所有报道，带综述；时间线可以切"最新在前"或"最早在前" |
| 主题页 (`/topics`) | 按公司、方向、内容形态分的主题聚合页 |
| 日报 / 周报 / 月报 | 每天一期日报，按规则编（一件事一条，有新进展才跟进）；每周一出周报，每月 1 日出月报，模型只写总述和栏目导读 |
| 搜索 | 标题摘要搜索，以及全文相关搜索 |
| 阅读设置 | 深浅色外观、字体选择；收藏和已读状态只存在读者本机浏览器里，不上传服务器，可以导出备份 |
| RSS / API / MCP / Agent 页面 | 同一份内容另外给 RSS 订阅器、程序、AI Agent 用，入口在 `/agent` |

公开页面对所有人看到的内容一样，不区分访客和管理员；读者的收藏、已读只存在自己浏览器里。

## 后台 (`/admin`) 能做什么

| 功能区 | 做什么 |
|---|---|
| 信源管理 | 增删信源、暂停/恢复、手动试抓看抓到了什么、查看每个信源最近的抓取健康状况 |
| 内容诊断 | 看某一条资料完整的处理链路（预筛/评分/写作/归组每一步的结果），人工更正分数、人工改标题摘要分类，撤销模型判断、改回公开可见性 |
| 精选评测（SelectBench） | 拿一批人工标注过的样本，跑一遍现在的评分标准，看选得准不准；换提示词或模型前先在这里对比 |
| 模型与评测 | 每一步（预筛、评分、写作、归组……）单独换一个模型，不用改代码或重启 |
| 设置 | 付费服务（模型、X、公众号、Jina）的预算上限：每分钟/每小时/每天最多调用几次，超过就自动暂停；通知目的地（飞书）开关 |
| 运行记录 | 每个定时任务、每次采集的执行历史和报错，排查"为什么没有新内容"从这里查 |
| 反馈管理 | 查看、处理读者通过反馈页提交的内容 |

后台只有管理员能登录（`/admin`，密码在 `.env` 的 `ADMIN_PASSWORD`），访客看不到任何后台页面或入口。

## 想调整"什么算重要、什么算噪声"

精选标准、门槛、分类标签、信源分级，全部是配置和提示词，不是代码。具体怎么改、怎么用自己标注的样本校准，看 [精选与校准](selection.md)；事件归组判断的逻辑和评测方法看 [事件归组](grouping.md)。改标准不需要工程师改代码，但建议先拿一两百条自己标注的样本验证过再上线。
